# STM32F103 三轮全向 ROS 移动机器人下位机

这是一个面向三轮全向移动机器人的 STM32 下位机工程。系统以 STM32F103RBT6 为主控，基于标准外设库和 FreeRTOS，实现 ROS 速度指令接收、三轮运动学解算、编码器测速、电机速度闭环、底盘速度反馈及通信失联保护。

仓库只包含 STM32 固件，不包含 ROS 上位机节点。当前版本重点完善了底盘实时控制和电机保护，并接入 MPU6050 原始数据采集。

## 当前实现

| 模块 | 当前方案 |
|---|---|
| 底盘 | 三轮全向轮，支持 `Vx / Vy / W` 复合运动 |
| 实时调度 | FreeRTOS 抢占式调度，控制任务 5 ms / 200 Hz |
| 轮速测量 | 5 ms 编码器差分采样，2 点滑动窗口统计最近 10 ms 脉冲 |
| 电机控制 | 速度前馈 + 带 `dt` 的抗饱和 PID |
| 目标整形 | 500/1000 mm/s² 加减速斜坡，单轮独立换向状态机 |
| 电机保护 | 轮速同比例限幅、PWM 限幅、最小有效 PWM、20 ms 换向关断 |
| ROS 通信 | USART3 115200 bps，DMA 循环接收 + IDLE 中断，DMA 非阻塞发送 |
| 安全机制 | ROS 指令 300 ms 超时硬停车，急停时同步清除控制状态 |
| IMU | MPU6050，250 Hz 原始六轴采样，上电陀螺零偏标定 |
| 状态显示 | OLED 10 Hz 显示轮速与底盘速度 |

## FreeRTOS 任务设计

系统将实时控制、通信、安全检查、IMU 采样和人机显示拆成独立任务。周期任务使用 `vTaskDelayUntil()` 保持固定节拍，电机控制任务拥有最高优先级。

| 任务 | 周期或触发方式 | 优先级 | 主要职责 |
|---|---:|---:|---|
| `ControlTask` | 5 ms / 200 Hz | 5 | 编码器采样、轮速计算、运动学、斜坡、PID 和 PWM 更新 |
| `RosRxTask` | 队列事件触发 | 4 | 从接收队列取字节并解析完整速度帧 |
| `SafetyTask` | 20 ms / 50 Hz | 4 | 检查 ROS 指令是否超过 300 ms 未更新 |
| `ImuTask` | 4 ms / 250 Hz | 3 | 读取 MPU6050 六轴原始数据并统计通信错误 |
| `RosTxTask` | 20 ms / 50 Hz | 2 | 回传底盘实际速度 |
| `DisplayTask` | 100 ms / 10 Hz | 1 | 刷新 OLED 状态 |

`ControlTask` 是正常运行时唯一写入电机 PWM 的任务。任务创建失败时立即停车；ROS 超时或急停时直接关闭三路 PWM，并清除目标斜坡、换向状态和 PID 状态。

## 轮速测量

三个编码器分别使用 TIM2、TIM3 和 TIM4 的编码器接口模式。定时器保持自由运行，每 5 ms 读取一次 16 位计数值，并通过有符号差分计算本周期增量；计数器自然回绕时不需要额外清零处理。

当前电机参数：

```text
编码器线数       = 11
正交四倍频       = 4
减速比           = 30:1
车轮直径         = 65 mm
每圈计数         = 11 × 4 × 30 = 1320 count/rev
每个计数对应距离 ≈ π × 65 / 1320 ≈ 0.15470 mm
```

测速采用长度为 2 的环形窗口：

```text
采样间隔 = 5 ms
统计窗口 = 2 × 5 ms = 10 ms
轮速     = 最近 10 ms 总脉冲 × 0.15470 / 0.010
```

因此控制量每 5 ms 更新一次，同时使用最近 10 ms 的脉冲统计减轻低速下单周期计数跳变。

## 三轮全向运动学

底盘中心到车轮的距离为 `117 mm`。代码中的逆运动学为：

```text
wheel1 =  0.5 Vy + 0.8660254 Vx + 117 W
wheel2 =  0.5 Vy - 0.8660254 Vx + 117 W
wheel3 = -1.0 Vy                + 117 W
```

其中：

- `Vx`、`Vy` 的单位为 mm/s；
- `W` 的单位为 rad/s；
- `wheel1~3` 的单位为 mm/s。

当任一目标轮速超过 `500 mm/s` 时，三个目标轮速按相同比例缩小，避免单独裁剪某个轮子后改变底盘合速度方向。

编码器轮速通过正运动学反解为底盘实际速度：

```text
Vx = (wheel1 - wheel2) / √3
Vy = (wheel1 + wheel2 - 2 × wheel3) / 3
W  = (wheel1 + wheel2 + wheel3) / (3 × 117)
```

## 电机闭环与保护

每个轮子独立维护目标、斜坡、换向状态和 PID 状态，最终控制量为：

```text
PWM = 1.24 × ramped_target
    + PID(ramped_target - measured_speed, dt = 0.005 s)
```

当前 PID 初值：

| 参数 | 数值 |
|---|---:|
| `Kp / Ki / Kd` | `4.0 / 5.0 / 0.01` |
| 控制 `dt` | `0.005 s` |
| 误差死区 | `3 mm/s` |
| 积分分离阈值 | `50 mm/s` |
| 积分状态限幅 | `±50` |
| PID 校正输出限幅 | `±1000` |

PID 的工程保护包括：

- 误差进入死区后停止校正并清除积分，减轻零速附近往复抖动；
- 只在误差不超过积分分离阈值时积分，大误差阶段由前馈和比例项快速响应；
- 积分状态和 PID 输出分别限幅；
- 输出饱和时撤销本周期新增积分，避免执行器饱和后继续积累；
- 积分项和微分项均使用实际控制周期 `dt`。

目标速度不会直接跳变：

- 加速斜率：`500 mm/s²`；
- 减速斜率：`1000 mm/s²`；
- 正反转切换：先按减速斜坡降到 0，PWM 关断保持 `20 ms`，再向相反方向加速；
- 三个轮子的换向状态彼此独立；
- 急停和通信超时属于安全事件，直接硬停车，不等待斜坡结束。

PWM 使用 TIM1 三通道输出，频率为 `10 kHz`，软件控制量归一化为 `0~1000`。最终硬件输出限制为 `±600`，非零控制量不足 `±50` 时提升到最小有效值，以跨过电机静摩擦区。以上阈值需根据实际驱动器和电机重新确认。

## ROS 串口通信

USART3 使用 `115200-8-N-1`，PB10 为 TX，PB11 为 RX。

接收端采用 128 字节 DMA 循环缓冲区配合 IDLE 空闲中断。中断只计算 DMA 新增数据范围并将字节写入 FreeRTOS 队列，帧解析放在 `RosRxTask` 中完成。发送端使用 DMA1 Channel2，避免 50 Hz 状态回传阻塞控制任务。

通用帧格式：

```text
0x55 0xAA | payload_length | payload | CRC8 | 0x0D 0x0A
```

- 多字节整数为小端序；
- CRC8 覆盖帧头、长度和数据区；
- 接收状态机同时检查帧头、数据长度、CRC8 和帧尾，可从半包、粘包或错误字节流中重新同步。

### 上位机下发速度指令

当前数据区长度为 7 字节，完整帧长度为 13 字节。

| 数据区字段 | 长度 | 类型与单位 |
|---|---:|---|
| `Vx` | 2 字节 | `int16_t`，mm/s |
| `Vy` | 2 字节 | `int16_t`，mm/s |
| `W` | 2 字节 | `int16_t`，实际 rad/s × 1000 |
| 控制位 | 1 字节 | 预留 |

### 下位机回传速度

数据区长度为 9 字节，完整帧长度为 15 字节，默认以 50 Hz 发送。

| 数据区字段 | 长度 | 类型与单位 |
|---|---:|---|
| 实际 `Vx` | 2 字节 | `int16_t`，mm/s |
| 实际 `Vy` | 2 字节 | `int16_t`，mm/s |
| 实际 `W` | 2 字节 | `int16_t`，实际 rad/s × 1000 |
| 扩展数据 | 2 字节 | 当前保留为调试字段 |
| 控制位 | 1 字节 | 预留 |

只有当前控制源为 ROS 时才启用 300 ms 指令超时判断；蓝牙调试指令不会被 ROS 超时逻辑误清除。

## MPU6050

MPU6050 使用 PC0/PC1 软件 I²C：

```text
MPU6050 VCC -> 3.3 V
MPU6050 GND -> GND
MPU6050 SCL -> PC0
MPU6050 SDA -> PC1
MPU6050 AD0 -> GND（地址 0x68）
```

当前配置：

- 加速度计量程：`±4 g`；
- 陀螺仪量程：`±500 °/s`；
- 采样率：`250 Hz`；
- 每次从 `ACCEL_XOUT_H` 连续读取 14 字节，获得同一批次的加速度、温度和陀螺数据；
- 初始化时检查 `WHO_AM_I`；
- 上电静止采集 200 组数据，约 0.8 s，计算三轴陀螺零偏；
- 记录有效采样次数和 I²C 读取错误次数。

当前只完成原始数据采集和零偏处理，没有启用 DMP，也没有将 IMU 数据直接融合进里程计。后续接入姿态融合前，需要先确认传感器安装方向和 ROS 坐标系。

## 编译与首次上电

1. 安装 Keil MDK 和 STM32F1 Device Pack。
2. 打开 `STM32 工程模版.uvprojx` 并全量编译。
3. 核对实际 MCU、晶振、启动文件和下载器配置。
4. 核对电机驱动、编码器、串口、OLED 和 MPU6050 接线。
5. 首次烧录时架空三个车轮，分别测试正反转和编码器极性。
6. 确认“正向 PWM 对应正向轮速反馈”，不要通过设置负 PID 参数修正接线或方向错误。
7. 先使用低速指令测试前馈，再逐步加入 PID 并记录三路电机的稳态 PWM。
8. 测试加减速、单轮换向、平移、旋转、复合运动和 ROS 断联停车。
9. 使用逻辑分析仪或 GPIO 翻转测量 5 ms 控制任务的执行时间和最坏抖动。

## 需要根据实车重新确认的参数

当前电机和控制参数用于工程开发与后续换型后的初始调试，并非对所有底盘都可直接使用。以下项目必须按实物重新确认：

- 编码器线数、倍频方式、减速比和车轮直径；
- 三路电机方向与编码器正负极性；
- 三个轮子的启动 PWM 和独立前馈系数；
- PID 参数、误差死区和积分分离阈值；
- 最大轮速、最大 PWM、斜坡加速度及 20 ms 换向保持时间；
- MPU6050 安装方向、零偏稳定性及坐标变换。

本工程没有添加 CAN 通信；MPU6050 尚未参与姿态或里程计融合；ROS 上位机、URDF、里程计发布、建图和导航代码不在本仓库中。
